# Reconciliation evidence and limits

This is an internal normalization/accounting kernel, not a selected provider integration. All positive records are original synthetic simulation fixtures. Actual live source permission, ownership, custody, API/SDK, finalization and complete settlement/withdrawal evidence remain unavailable under Task 20; the configured source reader is null.

Implemented: immutable bounded observations; stable provider/account/event/revision identity; globally exclusive order/fill/position attribution; exact financial fingerprinting; duplicate delivery without duplicate premium/liability; explicit source amendments with ledger reversals; pending fee/position dependencies; stale-status protection; authoritative fill-time classification; and owner/credential/mode/instrument checks. Missing fill time is retained as unverifiable. Late ingestion is distinct from an actually late fill. Claimable, settled and withdrawn states are separate; duplicated withdrawal proceeds become a discrepancy rather than a second payment.

A settled premium or quantity correction waits for the complete corrected settlement and position-coverage set, then applies the restatement atomically. Two real regressions exposed partial application and reuse of released collateral while a correction was pending; both now fail closed, with unresolved account discrepancies blocking new allocation. Explicit corrected quantities can revise Filled to Partially filled; a stale Submitted status cannot. Confirmed/finalized source metadata remains linked to its immutable observation.

Provider read calls run outside locks, with the exact credential revision rechecked before commit. Default worker jobs report unavailable source and retain reservations. The new-preparation pause does not substitute for source reconciliation or close funds. A financial worker was actually SIGKILLed after ledger commit; supported unlock/replay applied premium and liability once. No production messages, provider request, transaction, claim or withdrawal occurred.

Nine PostgreSQL reconciliation cases, four policy units and two normalized-shape contracts pass. Final full suite: 94 PostgreSQL cases, 102 units with TS/lint and web/worker builds, and 18 total contracts. Actual source-specific void/cancellation semantics, complete cancelled fill sets, multiple-position mapping and cash-settled product accounting remain explicit provider-dependent gates. A missing capability is not invented or treated as successful.

A related privacy regression showed a raw read-reference in owner registration output. Storage now projects approved evidence fields and hashes credential revisions; display APIs return only public/owner-safe facts. Legacy records are projected too. Source credentials are never copied to a UI or outbound message.
