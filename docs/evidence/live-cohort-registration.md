# Live performance registration boundary

Registration records separate read-access and aggregate-reporting consent from trade authority. All four weekly allocation plans and their uncovered fee reserve freeze before the first execution window. Each round still needs its own current starting-holdings verification; an early snapshot is explicitly not proof of a future balance. Fixture records are provisional and create no real sleeve, reservation, order, wallet signature or permission.

The internal provider-read contract requires the exact owner/account/read reference, canonical covered-allocation reference, isolated allocation, known size rules and required reserve, zero extra investment cash, source timestamp and record reference. Network reads occur outside locks; owner/revocation/read scope, post-wait cutoff and freshness are rechecked inside the write transaction. The default reader is Unavailable. No external provider API is invented and HTTP cannot supply evidence or gate flags. Verified-source activation remains blocked by the server-owned Gate 0 decision and Task 20 evidence.

A guild-specific season ID is insufficient for exclusivity. Append-only claims cover common UTC competition weeks for user/division, account and canonical provider allocation. Actual concurrent registration across different guild/season IDs leaves only one winner. Composite foreign keys bind claim and registration ownership. The immutable registration cannot delete a losing/missing sleeve; owner-reported decline/unfilled/holding is retained as an unverified report, not provider execution evidence. Owners retain their private records after departure; another identity gets none. Official cohort quality requires at least three members and all four verified non-deviating rounds. Existing legacy registrations without complete claims remain unverified; they are not silently promoted.
