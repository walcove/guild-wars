# Release procedure — disabled local candidate

No host, paid database, production bot, remote repository, HTTPS entry point or release is authorized/configured. [Service contract](../../ops/service-contract.json) is concrete about commands, instance counts, role/pool boundaries and probes; its null host/region/origin are release blockers, not invented deployment values. Choose a host only after provider eligibility, regional data/custody requirements, persistent-worker support, costs, secrets, backups/PITR and support ownership are approved. A simulation-only release does not complete the MVP.

Use the pinned Node 24 runtime, `npm ci` and one reviewed Git revision for both services. Run `npm run verify`, PostgreSQL migration/replay/integration, contracts, production browser suite and `npm run test:load` before packaging. The web output is `.next`; the worker bundle is `.local/worker.mjs` (built by `worker:check`). Keep lockfile and full build metadata; never rebuild one service from a different revision. Install production dependencies for these compiled outputs. No public SDK, registry, desktop/mobile package or Mini App is shipped.

Local commands: `npm run start` binds loopback; `node .local/worker.mjs` runs one persistent worker using WORKER_DATABASE_URL. Provide runtime secrets through an approved secret store only. Web uses guild_wars_app (10 connections); worker uses guild_wars_worker (2 critical + 3 background); migrations use guild_wars_migrator, never either runtime. One web/worker instance is the measured configuration. Recalculate total connections before any scaling. An approved reverse proxy must supply HTTPS and APP_ORIGIN consistently before release; forwarded origin/trust and secure Host cookies need hosted verification.

Application migrations precede worker schema/setup. Current migration scripts are deliberately restricted to the named local databases. A production migration command/managed-role installation requires the selected host contract and a reviewed target guard; do not bypass local guards or copy disposable passwords. Freeze Drizzle migrations 0000–0035 and the dependency lock. New financial or role-breaking migrations need maintenance, a tested backup, backward-compatibility evidence and a new release packet. CI runs migrations on a fresh database and again for idempotence. Existing frozen roster/result/source rules must not be rewritten to fit a release.

Liveness `/api/health` only confirms HTTP service execution. `/api/health?ready=1` checks DB reachability and worker/queue aggregate readiness, returning only ready/degraded with no private metrics. A worker heartbeat occurs every 15 seconds; older than 60 seconds is stale. `npm run ops:health` is a guarded local operator view of non-identifying aggregates. A host monitor must page a named on-call owner for stale worker, critical lag >30s, exhausted jobs, unknown orders and financial-source age >120s. The latter is conservative source-observation age, not proof an unchanged provider read failed. Native provider/quote-specific telemetry remains adapter dependent.

`GW_PAUSE_NEW_PREPARATION=true` prevents new live preparation at both the adapter boundary and canonical token service. It does not close positions, cancel submitted orders, release reservations or disable reconciliation/direct provider management. Deploy a pause to every web instance before rotating credentials. Restarting workers does not authorize orders. All release flags remain false and the immutable Gate 0/release record also rejects live preparation; environment variables cannot approve it.

Release requires a human-reviewed [packet](../evidence/release-readiness.md), native test-bot HTTPS evidence, real lifecycle permissions/records, operational owners and an explicit user decision. Only then may an authorized operator configure ingress/webhooks or perform separately confirmed financial validation. This document does not grant that permission.
