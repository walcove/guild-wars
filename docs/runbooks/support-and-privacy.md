# Support and privacy readiness

No production support owner, legal/eligibility review, data controller contact or retention policy has been appointed. These are release blockers. Name the operator, incident backup, privacy contact and provider escalation path in the release packet before collecting real member/provider records. Do not advertise a working support inbox or jurisdictional eligibility without evidence.

Collect only structured bot commands/callbacks needed by this application; no full-chat ingestion. Telegram identity, membership, sessions, owned provider relationships, immutable proposals/votes and verified records have distinct authorization scopes. Optional Solana ownership proof is not a trade, identity uniqueness check or provider permission. Personal amounts are owner-only unless separate aggregate reporting consent passes; report cohort aggregates only with at least three verified members and complete frozen coverage.

Logs allow only fixed component/event and bounded scalar timing/count/code fields. The worker logger discards library error text/meta, which may contain provider URLs, credentials or payloads. Health endpoints expose no member/order IDs, credentials, quote payloads or exception messages. Detailed financial records are accessed through authorized owner/admin services, never by copying raw request bodies into tickets. Local CLI aggregate output can still reveal activity levels; keep it in operator access.

For a report, ask for time, visible recovery message, release revision and a canonical record reference through the approved restricted channel. Never ask for a seed phrase, private key, Telegram bot token, signature, session cookie or provider secret. Triage identity and financial uncertainty before a duplicate action. Retain an append-only correction reason when evidence changes; never delete a losing forecast, cohort member or adverse fill to improve results.

A privacy/deletion request needs an authenticated identity check, scoped export and a reviewed retention/legal decision. Operational personal data should be minimized/anonymized where permitted; immutable financial/audit requirements need explicit retention rules. No automated deletion promise or legal retention period is invented. Native Telegram deletion, provider data rights and withdrawal of read/aggregate consent require provider-specific procedures before release.
